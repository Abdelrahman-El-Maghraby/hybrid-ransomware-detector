## Owner provider acceptance: real SMTP and S3-compatible endpoint

Use dedicated test resources you control; enter credentials locally in **Alerts
& cloud**, never in chat, a PR or a tracked `.env` file. Follow [OPERATIONS
section 8](../OPERATIONS.md#8-desktop-monitoring-alerts-and-cloud).

**SMTP:** configure verified TLS (465) or required STARTTLS (587), a test sender
and your own test recipient. Use **Send test e-mail**; confirm receipt and the
GUI delivery status. Exercise a benign test verdict/canary event in the disposable
profile, check metadata-only content, then temporarily make only the test SMTP
endpoint unavailable. Confirm the outbox retains the event and drains after
restoring connectivity. Check ordinary retry deduplication. Do not infer
exactly-once delivery when a remote acknowledgement is lost.

**S3:** start with uploads off and confirm no objects. Apply the installation-prefix
least-privilege policy and 90-day lifecycle rule documented in OPERATIONS using
the bucket administrator identity; the application's upload identity must not
have read/list/delete/configuration permissions. Enable upload and use **Test upload**. Scan a benign file named with a unique non-sensitive marker;
with a separate administrator identity inspect the uploaded report/event JSON.
The marker/path must be redacted, and no inspected-file bytes should be present.
Disable only the test endpoint temporarily, generate another report, verify the
local spool fills, then restore connectivity and confirm it drains.

Verify the endpoint enforces SHA-256 request checksums: with a disposable object
key and a provider SDK/tool, send known benign bytes with an intentionally wrong
`ChecksumSHA256` and `ChecksumAlgorithm=SHA256`. The server must reject it with a checksum-mismatch error; an access-denied or
unsupported-operation error does not establish checksum enforcement. A
successful PUT means the provider integrity assumption is not satisfied. Send
the correct checksum and confirm success. Record whether a response checksum
was returned; its absence is allowed only with server-side request validation.
Also verify conditional create-only PUT behavior and inspect the lifecycle
configuration (do not wait 90 days or claim expiration was observed). Keep
provider/account details private; report only supported behavior and results.

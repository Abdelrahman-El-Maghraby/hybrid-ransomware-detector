1. Class diagram: what makes up the scanner?

RansomwareScanner is the facade every entry point uses. It inherits its behaviour from five mixins, owns the 22-layer pipeline, the scoring matrix and the detection engines, and hands files to _IsolatedScan, which runs them in worker processes. Hollow triangles are inheritance. Filled diamonds are composition: the owner creates the part and keeps it. Solid open arrows are references that are not owned, and dashed arrows are dependencies.

Checked in the code
  • RansomwareScanner inherits from the five mixins in this order: StagedPipelineMixin, ProtectionMixin, ReportMixin, ExternalLookupsMixin, TextExtractionMixin (engine/scanner.py).
  • A layer never calls another layer. Layer.run(scanner, ctx) reaches its engine through the scanner (YaraLayer calls scanner.yara_engine) and writes its result and its typed signal into the ScanContext (engine/layers.py).
  • The callers do not scan by themselves: ScanController, FolderMonitor and MailboxScanner call scan_one() or _scan_targets() on a RansomwareScanner, and _ScanService calls scan_isolated() with the scanner it owns.
  • default_pipeline() builds 22 layer objects from 19 Layer subclasses: ContainerLayer is created four times, once per handler (mail, archive, web, embedded).
  • Layer and ContainerHandler are plain base classes whose methods raise NotImplementedError; only LLMBackend is declared abstract (ABC).
  • The six *_listener attributes are callbacks that _worker_main() sets inside a worker process; they send the pipe messages shown in the activity diagram.
  • Each _Worker starts a child process that builds its own RansomwareScanner; _IsolatedScan keeps the caller's scanner only to build failure results and to call on_result().
  • The scanner's sandbox attribute is a CapeClient, or an IntelSandbox when the intel service is used (Docker); its llm_backend is then an IntelLLMBackend.

  association   the object keeps a reference to something it does not own
  dependency    a parameter, a call or a creation (run(scanner, ctx), ...)

def width_of(name: str, rows: Sequence[str], stereotype: str = "") -> int:
    need = max([text_width(name, 14, True), text_width(stereotype, 12)]
               + [text_width(r, 12.5) for r in rows])
    return math.ceil(need + 20)


def tree(d: Diagram, parent_point, rail_x: float, children: Sequence[Box], bus_y=None,
         name: str = "") -> None:
    """A shared generalisation: one hollow triangle at the parent, a rail, and a
    short tick to every child."""
    px, py = parent_point
    last = children[-1]
    if bus_y is None:                       # parent to the left of the rail
        d.edge([(rail_x, py), (px, py)], "gen", name=name, check=False)
        d.edge([(rail_x, min(py, children[0].cy)), (rail_x, last.cy)], "line", name=name,
               check=False, radius=0)
    else:                                   # parent above: trunk down to a bus
        d.edge([(rail_x, bus_y), (rail_x, last.cy)], "line", name=name, check=False, radius=0)
    for child in children:
        d.edge([(rail_x, child.cy), (child.left, child.cy)], "line", name=name, check=False)

Three primary actors reach Aegis Sentinel: a desktop user, an administrator and an API client. Seven external systems take part when they are configured. The GUI, the CLI and the REST API are interfaces, so they appear as a tag on each use case that offers them, not as actors.

3. Activity diagram: how does one file get a verdict?

One file in an isolated scan, which is the default. The entry point submits it, the parent process hands it to a worker over a pipe and watches the clock, the worker runs the pipeline and reports back, and the parent decides what the wait produced. Solid arrows are control flow. Dashed arrows are messages on the pipe or calls to a service.

Checked in the code
  • The worker runs the fast layers one after another, then emulation, ml, llm and virustotal together on up to four threads (_run_together, engine/staging.py). In a worker with a sandbox configured, the sandbox layer runs last, on its own.
  • A provisional snapshot is sent only while every layer still running is VirusTotal or the LLM (_publish_pending); a stalled parser, classifier or emulator is treated as a failure, not as an external time-out.
  • At the time limit the parent keeps a settled or completed snapshot as it is, turns a provisional one into a partial result with stopped_result(), and falls back to failure_result() when it holds none (_IsolatedScan._step).
  • failure_result() scores the scan_failed indicator (25 points, Medium). Member evidence reported before the failure is kept when it scores higher.
  • In the code the result is handed to on_result() first and the stopped worker is replaced straight after; the fork shows that both happen.
  • Automatic quarantine belongs to collect(), the on_result callback of _scan_targets(). scan_one() and the REST API pass their own callback, so they never quarantine.
  • An allowlisted file skips the heavy layers unless its MD5 is also in the local malware database. A sandbox report found in the result cache is used without submitting the file.
  • Not drawn: cancelling a batch (the GUI's Stop) hands out no further files, and a file already in a worker still finishes; with ISOLATE_SCANS=0 (development only) scan_file() runs in the caller's process and none of the pipe messages exist.

4. Flowchart: how does the whole system fit together?

Six intake channels feed one scan engine. Every file goes through the same detection stages in an isolated worker, is scored, and comes back to the parent, which sends the result to the destinations that channel uses. The coloured chips on a destination name the channels that reach it.

Checked in the code
  • GUI and CLI both reach scan_one() for a single file. For the configured folders the GUI calls scan_all_directories() itself, and scan_directory() for one folder it names; the CLI's --scan-now and the background service call run_scan(), which checks the canaries first and then calls it (engine/scanner.py).
  • FolderMonitor.scan_batch() and MailboxScanner.run() hand their files straight to _scan_targets(); the REST API calls scan_isolated() itself through _ScanService.scan() (core/folder_watch.py, core/mailbox.py, api/server.py).
  • Isolation fails closed: when no worker can start, the file is not parsed in the parent. The CLI exits 3, the API answers 503, the GUI offers a retry (engine/workers.py).
  • Automatic quarantine runs in the collect() callback of _scan_targets(), so it applies to folder, monitor and IMAP scans, not to scan_one() or the API.
  • The API path sends e-mail alerts only: _Alerts clears webhook_url, and it writes no report files or JSON Lines (api/server.py).

The optional Kubernetes deployment in deploy/kubernetes, drawn on its own so the Docker view above stays as it is. A purple frame is a Pod: one network namespace, which is what a NetworkPolicy controls, so the proxy and analysis containers share one interface. A thick red frame is a container. There is no intel service on Kubernetes yet, so no external service is reachable or configured. These manifests have not been run on a cluster.

Checked in the code
  • One Pod, two containers: analysis (python -m api.server, uid 10001) and proxy (the aegis-sentinel-proxy image with deploy/Caddyfile, uid 10003), joined by api.sock in a memory-backed emptyDir, as in docker-compose.yml (deploy/kubernetes/base/analysis.yaml).
  • Containers in one Pod share its network namespace, and NetworkPolicy applies to Pods, not containers. aegis-default-deny selects every Pod for ingress and egress with no rule; aegis-allow-https admits TCP 8443 to the analysis Pod. No policy allows egress (deploy/kubernetes/base/networkpolicy.yaml).
  • The init container prepare-state creates RansomwareScanner/data in the state claim as uid 10001 (the runtime would create that mount point as root). Then isolation-gate and the analysis readiness probe run isolation_gate.py from the ConfigMap aegis-isolation-gate: a connection that succeeds or a DNS answer fails them. Liveness asks only /health on the socket.
  • Secrets: aegis-api-token mounted only in analysis, aegis-tls only in proxy, both mode 0440; automountServiceAccountToken false; no Role. No external-service credential exists in this Pod (check_manifests.py refuses one); with components/intel, only the intel Pod holds them.
  • Claims aegis-analysis-state and aegis-content are ReadWriteOncePod; analysis mounts the content read-only (both in the volume and the mount). The content Job (deploy/kubernetes/jobs/content-update.yaml) is the only writer and can mount it only while analysis is scaled to zero.
  • Differences from Docker (diagram 5): a Pod interface exists where Docker has none; /tmp is an emptyDir without noexec; the process limit is the node's podPidsLimit; intel is optional and reached over TLS on one port instead of a socket. Runtime behaviour on a cluster is unverified (deploy/kubernetes/verify-cluster.sh).

TITLE = "Kubernetes deployment: Pods, containers and what separates them"

PROC = "#eff6ff"        # a process

STORE = "#f8fafc"       # claims, volumes, API objects

BOUND = "#b91c1c"       # container boundary stroke

def container(d: Diagram, x: float, y: float, w: float, h: float, title: str,
              body: List[str], name: str) -> Box:
    """A container: thick solid boundary, title and wrapped body."""
    return d.titled(x, y, w, title, body, h=h, fill=CONT, stroke=BOUND, sw=3, rx=6, name=name)

Graphify network (reference)

The diagrams started from the Graphify code graph of the repository: 6,366 nodes, 15,577 edges and 335 communities, built from the tracked source, tests and configuration with no LLM. Before drawing, the graph was built again from a git archive of b6966f8 and compared with the stored one: the same nodes, the same edges and the same communities.

graphify-code-graph.html: the interactive network, one node per community, named after its main symbol and that symbol's own file. It loads the vis-network library from unpkg, so it needs an internet connection.

The graph supplied the class list, the 88 inheritance edges (69 of them between application classes, all read from the code) and the hubs (RansomwareScanner, ContainerExtractor, ScoringMatrix, ScanContext, Signals). It is a static graph, so it cannot see what happens at run time. The pipe messages between worker and parent, the listener callbacks, the thread pool, the time-out outcomes and the network calls were read in the source files and are drawn from there.

Editing the diagrams

  • Each diagram is defined in one Python file in uml-diagram-sources/: texts, positions and connectors. Change it and run python3 build_diagrams.py in that folder. The six SVG files and this page are written again. Python 3.9 or later; nothing to install.
  • The build stops when a label no longer fits its box, when two nodes overlap or when a connector runs through a node it is not attached to.
  • The SVG files are plain SVG with real text, so they also open in Inkscape, Figma or draw.io for a one-off change. A later build overwrites such changes.
